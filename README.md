# ⚖️ نظام إدارة الموارد البشرية والقضايا القانونية (HR & Case Management System)

منصة متكاملة ومتقدمة مبنية بأحدث تقنيات الويب لإدارة شؤون الموظفين، تتبع القضايا القانونية، التنبيهات الذكية عبر تيليجرام، وتخطيط الجلسات. مجهزة بالكامل للرفع على استضافة **Vercel** والربط مع **Firebase**.

---

## 🎨 مميزات المنصة الرئيسية

1. **إدارة القضايا والطلبات**:
   - استقبال طلبات العملاء وتحسينها وتحويلها لقضايا بكبسة زر.
   - تتبع الجلسات وتنبيهات مواعيدها تلقائياً.
   - أرشيف كامل للملفات وتتبع التغييرات.

2. **نظام مالي وجلسات ذكي**:
   - متابعة السدادات والدفعات المالية للعملاء والمصاريف.
   - جدولة الجلسات الإلكترونية وتصنيفها.

3. **نظام الإشعارات الفوري**:
   - تنبيهات Telegram فورية للأحداث وتغيير الحالات.
   - تنبيهات ذكية قبل الجلسة (7 أيام، يوم واحد، 30 دقيقة).
   - إشعارات داخلية داخل التطبيق (In-App notifications).

4. **الأمان والمصادقة**:
   - تسجيل دخول آمن بالكامل مع إمكانية استعادة كلمة المرور عبر البريد الإلكتروني.
   - أدوار وصلاحيات مخصصة لكل مستخدم.

---

## 🛠️ التقنيات المستخدمة

- **Frontend**: React 18 / 19, TypeScript, Tailwind CSS, Motion, Recharts
- **Build Tool**: Vite v6
- **Database & Auth**: Firebase Firestore + Firebase Auth 
- **Hosting**: Vercel

## 🚀 التشغيل المحلي (Local Development)


## 📦 هيكلة المجلدات والملفات المهمة

- `src/` - يحتوي على كل شيفرة التطبيق البرمجية (المكونات، الصفحات، الخطافات Hooks).
- `vercel.json` - ملف تكوين الاستضافة على Vercel لضمان توجيه مسارات التطبيق (Routing) دون أخطاء 404.
- `vite.config.ts` - إعدادات البناء، تقسيم الحزم (Code Splitting)، دمج برمجية Tailwind.
- `.env.example` - المتغيرات البيئية المطلوبة لتشغيل الاتصال بـ Firebase وتيليجرام.

## ⚡ حل مشكلة خطأ 404: NOT_FOUND على Vercel

### 🌟 تشخيص وفهم المشكلة:
في تطبيقات الصفحة الواحدة (SPA) مثل React مع React Router، بمجرد إعادة تحميل الصفحة داخل مسارات فرعية (مثل `/dashboard` أو `/employees`) مباشرة في المتصفح، يقوم خادم الاستضافة (Vercel) بالبحث عن ملف حقيقي باسم `dashboard/index.html` أو `dashboard` في مجلد البناء. لعدم توفر هذا الملف، يعود الخادم بخطأ **404 NOT FOUND**.

### 🛠️ الحل الجذري:
قمنا بإنشاء ملف `vercel.json` في مجلد المشروع الرئيسي ليقوم بعملية **Rewrite** لجميع طلبات المسارات غير الموجودة وتحويلها بالكامل لتعالج عبر `index.html` لتتولى مكتبة React Router توجيهها داخلياً.

محتوى ملف `vercel.json` المعتمد:
```json
{
  "version": 2,
  "cleanUrls": true,
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

## ☁️ خطوات النشر على لوحة تحكم Vercel Dashboard

لضمان بناء سليم بنسبة 100% دون أي مشاكل، قم بضبط إعدادات لوحة التحكم في موقع Vercel كالتالي:

| الحقل | القيمة الدقيقة المطلوب إدخالها |
| :--- | :--- |
| **Framework Preset** | `Vite` |
| **Build Command** | `npm run build` |
| **Output Directory** | `dist` |
| **Install Command** | `npm install` |
| **Root Directory** | اتركه فارغاً `.` |
| **Node.js Version** | `18.x` أو `20.x` |

### إعداد المتغيرات البيئية (Environment Variables) في Vercel:
اذهب إلى **Settings -> Environment Variables** وضف قيم المتغيرات كما هي مسجلة في ملف `.env.example` مع الحرص على استخدام البادئة `VITE_` ليتعرف عليها محرك Vite.

## 📂 أوامر رفع المشروع لـ GitHub

إذا أردت نقل ورفع التعديلات للفرع الرئيسي `main` تمهيداً للبناء التلقائي في Vercel، تتبع الأوامر التالية بالترتيب:

```bash
# 1. تهيئة مستودع Git (إذا لم يكن مهيئاً)
git init

# 2. إضافة جميع الملفات الجديدة والمعدلة
git add .

# 3. حفظ التغييرات مع رسالة وصفية
git commit -m "chore: fix Vercel SPA 404 routing error and optimize build code splitting"

# 4. إعادة تسمية الفرع الحالي لـ main
git branch -M main

# 5. ربط المستودع البعيد (تأكد من استبدال الرابط برابط مستودعك الفعلي)
git remote add origin https://github.com/USERNAME/REPOSITORY.git

# 6. رفع الملفات وتفعيل التتبع للفرع الرئيسي
git push -u origin main -f
```
